## 1. 장표 구성안 (발표 순서 그대로, 약 16분)

PPT 는 직접 만든다. 아래는 장마다 **넣을 것 · 말할 것 · 근거**다. 말할 것은 그대로 읽어도 되는 길이로 적었다.

**듣는 사람 대부분이 게임을 잘 모른다**고 보고, 기술 이야기 전에 배경 장표 세 장(2~4)을 둔다 — "게임 등급분류가 무엇인지 → 어떻게 정해지는지 → 왜 미리 점검하는 도구가 필요한지".
게임 용어는 처음 나올 때 한 번 풀어 준다(이 절 끝의 1-1). 발표 시간이 짧게 정해지면 10·11번을 줄인다.

### 장표 1. 표지 — 한 줄 소개 (20초)
- 넣을 것: 제목 "게임 등급분류 사전 점검 에이전트", 과제 2, 이름.
- 말할 것: "게임을 출시하기 전에 '몇 세 이용가가 나올지' 미리 점검해 주는 AI 에이전트를 만들었습니다."

### 장표 2. 배경 ① — 게임 등급분류가 무엇인가요? (1분)
- 넣을 것: 영화 관람등급과 나란히 놓은 그림 한 장 + 네 가지 등급.

  | 등급 | 뜻 (게임산업법 제21조 제2항) |
  | --- | --- |
  | 전체이용가 | 누구나 이용할 수 있다 |
  | 12세이용가 | 12세 미만은 이용할 수 없다 |
  | 15세이용가 | 15세 미만은 이용할 수 없다 |
  | 청소년이용불가 | 청소년은 이용할 수 없다 |

  - **누가 정하나**: 게임물관리위원회(제16조 — 청소년 보호, 사행심 방지, 불법 게임물 유통 방지가 목적). 문화체육관광부가 지정한 사업자가 직접 매기기도 한다(자체등급분류, 제21조의2).
  - **꼭 받아야 하나**: 게임을 팔거나 서비스하려면 **만들어 내놓기 전에** 받아야 한다(제21조 제1항). 등급과 내용정보를 게임에 표시해야 한다(제33조).
  - **안 받으면**: 등급을 받지 않은 게임을 유통하는 것은 금지(제32조)이고, 5년 이하 징역 또는 5천만원 이하 벌금 대상이다(제44조).
- 말할 것: "영화관에서 보는 '12세 관람가', '청소년 관람불가'와 같은 제도가 게임에도 있습니다. 한국에서 게임을 팔려면 출시 전에 반드시 등급을 받아야 하고, 안 받고 팔면 처벌받습니다."

### 장표 3. 배경 ② — 등급은 어떻게 정해지나요? (1분)
- 넣을 것
  - 위원회는 게임 안의 표현을 **일곱 가지 항목**으로 본다 — 폭력성 · 선정성 · 공포 · 언어(욕설) · 약물 · 범죄 · 사행성(도박을 흉내 낸 요소).
    항목마다 수위가 네 단계이고, 그 단계가 곧 네 등급에 대응한다(위원회 사례집 요약표).
  - 예: 폭력성 — "경미한 폭력 표현"이면 12세, "사실적인 폭력 표현"이면 15세, "과도한 폭력 표현"이면 청소년이용불가.
  - 그런데 법의 기준 문구는 추상적이다 — 전체이용가는 "청소년에게 유해한 표현이 없는 게임물", 청소년이용불가는 유해한 표현이 "사실적으로 표현되어 있는 게임물"(시행규칙 제8조).
- 말할 것: "등급은 게임 속 표현을 일곱 가지로 나눠 수위를 보고 정합니다. 문제는 '유해한 표현이 없는', '사실적으로 표현된' 같은 말이 사람마다 다르게 읽힌다는 것입니다."

### 장표 4. 왜 만들었나 — 개발 동기 (1분)
- 넣을 것: 네 줄.
  1. **출시 전에 알아야 계획을 세운다** — 몇 세 등급이냐에 따라 누구에게 팔지, 어떻게 광고할지가 달라진다. 심의 결과가 예상보다 높게 나오면 내용을 고치거나 대상을 바꿔야 한다.
  2. **그런데 미리 가늠하기 어렵다** — 기준 문구가 추상적이다(장표 3).
  3. **판단 재료는 공개돼 있지만 흩어져 있다** — 위원회가 공개한 실제 결정(2024-01 ~ 2026-09, 3,190건), 사례집 기준표, 법령 조문. 사람이 일일이 찾아 비교하기 어렵다.
  4. **전공** — 게임 산업 전공. 국내에 게임을 내려면 누구나 거치는 절차라 실제로 쓸모 있는 주제를 골랐다.
- 말할 것: "그래서 '실제 결정 사례와 공식 기준표, 법령을 근거로 출시 전에 등급을 미리 점검해 주는 도구'를 만들기로 했습니다. 작은 개발사나 기획자가 심의를 넣기 전에 참고용으로 쓰는 것을 생각했습니다."

### 장표 5. 문제 — LLM 에게 그냥 물으면 (1분)
- 넣을 것: LLM 단독으로 직접 재현한 문제 5개 — 숫자와 함께.

  | 문제 | 재현 |
  | --- | --- |
  | 제도를 지어낸다 | "청소년이용불가는 14세 이상", "수수료 1000원" — 제도 문의 2/17 |
  | 점검 요청을 못 알아듣는다 | 분류 15/30 — 점검 요청 15개 모두 일반 대화로 |
  | 등급과 근거가 어긋난다 | "전체이용가"라면서 내용정보 7개 전부 — 정밀도 0.16, 정확도 14/40 |
  | 설명이 없어도 등급을 찍는다 | 되묻기 6/12 |
  | 검수가 형식만 본다 | 오염 보고서 0/7 탐지 |
- 말할 것: "그럼 요즘 AI 에게 물어보면 되지 않을까요? 직접 해 보니 이렇게 지어내거나 앞뒤가 안 맞는 답을 냈습니다."

### 장표 6. 해결 방향 (1분)
- 넣을 것: 순서도 1장([`05-presentation-notes.md`](05-presentation-notes.md) 3절) + 핵심 문장.
- 말할 것: "**LLM 은 '항목별로 어느 정도 표현인가'만 판단하고, 등급 계산과 근거 확인은 코드가 합니다.** 자료는 위원회 실제 결정 3,190건, 기준표, 법령 148개 조문입니다."

### 장표 7. 주제 및 세부 기능 + 기술 요소 (2분)
- 넣을 것: [`04-report.md`](04-report.md) 2절 표의 줄인 판(순번 1~10, 7번 제외 표시) + 기술 요소 표(3절).
- 말할 것: 기능마다 한 문장. 특히
  - "Multi-Agent 는 검토하고 뺐습니다. 등급은 가장 높은 항목 하나로 정해져서 항목을 나눠 심사해도 정보가 늘지 않고, 과대평가와 지연만 커집니다."
  - "부품마다 스위치가 있어서 모두 끄면 LLM 단독이 됩니다. 이것이 Before 입니다."

### 장표 8. 시연 (2분)
- 넣을 것: 웹 화면 캡처 또는 실시간 시연(순서는 [`05-presentation-notes.md`](05-presentation-notes.md) 9절).
  1. "우리 게임 몇 세 받을까요?" → 되묻기 → "PC 액션 게임이에요. 칼로 적을 베면 피가 튀어요" → 판정
  2. "게임 등급은 몇 가지로 나뉘고 각각 무슨 뜻이에요?" → 법령 근거 답
  3. "게임물관리위원회 전화번호 알려 주세요" → 답할 수 없음
- 말할 것: 화면의 진행 표시를 짚는다 — "분류 → 비슷한 사례 5건 → 통계는 MCP Tool, 기준표는 MCP Resource → 항목별 판정 → 검수 통과".

### 장표 9. Before/After (2분)
- 넣을 것: [`04-report.md`](04-report.md) 3-1 표(정확도 A·B, 분류, 되묻기, 검수, 제도 문의, 지연·비용).
- 말할 것: "같은 커밋에서 스위치만 바꿔 쟀습니다. 모델도 입력도 같습니다." + "과소평가(더 위험한 오류)가 25 → 15건으로 줄었습니다."
- 반드시 같이 말할 것: 문항 수("40개 중 19개"), 대가(판정 4.7 → 16초, 회귀 쿼리 11턴 13.6 → 319초, 비용 약 4.7배).

### 장표 10. 정직한 비교 — 기준선과 더 강한 모델 (1분 30초)
- 넣을 것: 기준선 표(사례 5건 다수결 22/40 > 에이전트 19/40) + OpenAI 보조 표(상승폭).
- 말할 것: "짧은 설명에서는 비슷한 사례의 다수결이 더 낫습니다. 더 강한 모델로 재 보니 분류 같은 단순 보조의 이득은 사라졌지만, 근거·검증 구조(제도 문의 +13)와 기준표 판정(상세 설명 +6)의 이득은 남았습니다."

### 장표 11. 발견 — 데이터 쏠림 (1분 30초)
- 넣을 것: 모바일 결정 표(실제 전체이용가 293건 중 필터 뒤 34건만 남음), 77% → 35%.
- 말할 것: "귀여운 퍼즐이 청소년이용불가로 나왔습니다. 처음엔 짐작으로 원인을 적었다가, 원자료와 법령(제21조의10)으로 확인해 보니 제가 만든 필터가 간소화 등급분류 결정을 지운 것이었습니다. 고친 뒤 퍼즐은 전체이용가로 돌아왔지만, 개요 없는 사례가 '가장 비슷한 사례'로 뽑히는 새 약점이 생겨 A 가 22 → 19 로 내려갔습니다."

### 장표 12. 한계와 트레이드오프 (1분 30초)
- 넣을 것: 4개만 고른다.
  1. 과소평가를 줄인 대가로 과대평가가 늘었다(평범한 게임 1건 청불) — 과소평가가 더 위험해서 택했다.
  2. 느리고 비싸다 — 임베딩 모델(사례 1,751건·조문 148개를 기동 때 임베딩, 캐시)과 큰 LLM 3회 호출.
  3. 무한 루프는 상한으로 막았다 — 재조사는 범위 3단계(장르+플랫폼 → 플랫폼 → 전체)에서 끝나고, 재작성은 최대 3회.
  4. 법령 해석 오답 1건이 검수를 지나갔다.
- 말할 것: "지연은 3회 반복한 중앙값이고, 정확도는 온도 0 이라 반복해도 같았습니다. 다만 문항이 40개 안팎이라 2~4문항 차이는 우연일 수 있습니다."


- 하는 일

  4. `combine` 이 결합 규칙 R1 로 "가장 비슷한 실제 사례의 등급"을 하한으로 쓴다.
- 왜: LLM 에게 등급을 바로 물으면 등급과 근거가 어긋났다. 계산을 코드로 옮기면 **보고서의 등급과 근거가 늘 맞는다.**
  R1 은 과소평가(더 위험한 오류)를 줄이려고, 결과를 보기 전에 적은 후보 5개 중 개발용 문항으로 골랐다.

근거: 게임산업법 제21조(등급분류·4등급), 제16조(위원회), 제32조·제44조(안 받고 유통하면 금지·처벌).

<details><summary>0-2. 왜 출시 전에 등급을 미리 알아야 하나요? 그리고 왜 미리 알기 어렵나요?</summary>

등급에 따라 누구에게 팔고 어떻게 광고할지가 달라지고, 결과가 예상보다 높으면 내용을 고치거나 대상을 바꿔야 한다.
그런데 기준 문구("유해한 표현이 없는", "사실적으로 표현된")가 추상적이고, 판단 재료(실제 결정·기준표·법령)는 흩어져 있다.
</details>

<details><summary>1. 이 에이전트에서 LLM 이 하는 일과 코드가 하는 일을 나눠 말해 보세요.</summary>

LLM: 질문이 애매할 때 분류, 7항목의 단계와 근거 판단, 보고서 작성, 검수의 뜻 판정, 법령 답변.
코드: 근거 구절 확인, 등급 계산(단계 최댓값 + 사례 하한), 사례·숫자 대조, 법령 인용 검사, 되묻기 규칙.
</details>

<details><summary>2. Before 와 After 는 무엇이 다르고, 왜 공정한 비교인가요?</summary>

같은 프로그램·같은 모델·같은 입력에서 에이전트 부품 스위치만 끈 것이 Before(LLM 단독), 켠 것이 After 다.
같은 커밋에서 쟀으므로 차이는 에이전트 구조 때문이라고 말할 수 있다.
</details>

<details><summary>3. 등급을 왜 "가장 높은 단계"로 정하나요?</summary>

사례집 요약표의 4단계가 곧 연령 등급이라, 한 항목이라도 청불 수준이면 그 게임은 청불 기준에 해당한다. 평균을 내면 청불 수준의 폭력이 다른 항목에 묻힌다.
다만 실제 심의는 맥락까지 보므로 요약 규칙이다(결정 0011 한계).
</details>

<details><summary>4. 결합 규칙 R1 은 무엇이고, 어떻게 골랐나요?</summary>

기준표 판정과 가장 비슷한 실제 사례의 등급 중 높은 쪽을 쓰는 규칙. 후보 5개와 고르는 기준(정확도 → 과소평가 적음 → 단순함)을
결과 전에 커밋하고, 평가셋과 겹치지 않는 개발용 38문항으로 골랐다(18/38, 지금 방식 14).
</details>

<details><summary>5. R1 의 대가는?</summary>

과대평가가 늘었다 — 평가셋 B 4 → 10, 평범한 요리 경영 게임을 청불로(가장 비슷한 사례가 선정성 때문에 청불). 과소평가가 더 위험해서 감수했다.
</details>

<details><summary>6. 데이터 쏠림의 원인과 수정, 그리고 부작용은?</summary>

"개요 있음" 필터가 간소화 등급분류(제21조의10, 청불 제외) 결정을 지워 모바일 사례의 77%가 청불이 됐다. 개요 없는 결정도 넣어 35%로 고쳤다.
부작용: 개요 없는 사례가 제목·장르·플랫폼만으로 "가장 비슷한 사례"로 뽑혀 평가셋 A 가 22 → 19 로 내려갔다.
</details>

<details><summary>7. MCP 에서 Tool 과 Resource 를 하나씩 예로 들어 보세요.</summary>

Tool: `rating_stats(genre, platform)` — 같은 장르·플랫폼의 등급 분포를 계산해 준다. Resource: `criteria://descriptors`(기준표), `law://game-industry/articles`(법령 조문) 등 읽기 전용 자료.
</details>

<details><summary>8. 그래프가 무한 루프에 빠지지 않는 이유는?</summary>

재조사는 범위를 장르+플랫폼 → 플랫폼 → 전체로만 넓혀 최대 두 번, 재작성은 `MAX_ATTEMPTS = 3` 으로 끝난다.
</details>

<details><summary>9. 제도 문의에서 "답할 수 없음"이 나오는 조건 네 가지는?</summary>

① 모델이 답할 수 없다고 하거나 답이 비었다 ② 근거 조문을 밝히지 않았다 ③ 검색하지 않은 조문을 인용했다 ④ 답의 숫자가 인용 조문에 없거나, LLM 대조에서 조문과 맞지 않는다고 나왔다.
</details>

<details><summary>10. 에이전트가 단순한 방법보다 못한 경우는?</summary>

한 문장 설명에서는 비슷한 사례 5건의 다수결(22/40)이 에이전트(19/40)보다 높다. 평범한 게임에서는 LLM 단독이 하나 더 맞혔다(9 vs 8).
</details>

<details><summary>11. 더 강한 모델(OpenAI)이면 에이전트가 필요 없나요?</summary>

분류처럼 단순한 보조의 이득은 사라졌지만(30/30 → 29/30), 근거·검증 구조(제도 문의 +13)와 기준표 판정(상세 설명 +6)의 이득은 남았다.
다만 되묻기 조건이 qwen 기준이라 gpt-4o 에서는 평범한 게임도 되물었다(10 → 6).
</details>

<details><summary>12. 평가셋을 보고 결과를 맞춘 것 아닌가요?</summary>

평가셋은 기능 코드보다 먼저 커밋했고, 판정 기준(라우터 0.04)은 예시 문장으로, 결합 규칙은 개발용 문항으로 골랐다. 데이터 수정 뒤 평가셋을 두 번째로 본 것은 한계로 밝혔다.
</details>

<details><summary>13. Multi-Agent 를 왜 넣지 않았나요?</summary>

항목별 심사 에이전트 7개로 나눠도 등급은 최댓값 하나로 정해져 정보가 늘지 않는다. 판정을 7번 따로 하면 그중 하나라도 높게 볼 확률이 커져 과대평가가 늘고,
로컬 모델은 요청을 하나씩 처리해 지연이 약 7배가 된다(추정). 정답 데이터에 항목별 단계가 없어 효과를 잴 수도 없다.
</details>

<details><summary>14. 임베딩을 도입해서 생긴 비용은?</summary>

기동 때 사례 1,751건·조문 148개·예시 문장을 임베딩한다(파일 캐시로 두 번째부터 빠름). 임베딩 모델용 Ollama 가 늘 떠 있어야 하고, OpenAI 로 띄워도 필요하다.
</details>

<details><summary>15. 보고서 검수에서 코드 검사를 LLM 판정보다 앞에 둔 이유는?</summary>

등급·사례 제목·숫자 대조는 정답이 정해진 일이라 코드가 싸고 정확하다. 앞에서 떨어지면 LLM 판정 호출을 아낀다.
</details>
