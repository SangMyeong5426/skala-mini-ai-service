## 진행 계획 양식

과제 1은 개선/신규 포인트 목록, 과제 2는 주제와 세부 기능 목록을 쓴다.
열은 `순번 | 영역 | 무엇을 바꾸나 | 추가 설명` 이다. 이 저장소의 원본은
[`01-plan.md`](01-plan.md)다.

자료가 든 가상 예시의 영역은 아래와 같다(요약).

| 영역 | 예시 |
| --- | --- |
| RAG | 키워드로 incident_type을 매핑하던 부분을, runbook을 벡터 DB에 임베딩(메타데이터에 incident_type)해 두고 의미 기반으로 찾게 바꾼다 |
| 모듈화 | 단일 파일의 그래프 노드를 별도 모듈로 분리 |
| 그래프 개선 | research 노드를 로그·메트릭·런북 분석 서브에이전트(compiled subgraph)로 쪼개고, 메인 그래프가 이들을 부르는 supervisor-of-supervisors 구조 |
| 그래프 개선 | LangGraph `interrupt()`로 위험 조치(예: 서비스 재시작 제안) 전에 사람 승인을 받는 노드를 write → validate 사이에 삽입 |
| 메모리 | 대화가 길어지면(예: 10턴 이상) 과거 턴을 LLM으로 요약·압축 — 토큰 비용·컨텍스트 크기 실측 비교 |
| 평가 | 키워드 매칭 평가에 "응답이 수집된 수치를 정확히 인용했는가"를 LLM으로 채점하는 평가자 추가 |
| 그래프 개선 | 프롬프트 조회, 대상 시스템 누락 시 기본 시스템 폴백 등 하드코딩 개선 |
| 데이터 보강 | incident_type 등 샘플 데이터를 확장해 추가 데이터 생성·활용 |

## 평가 기준

| 항목 | 배점 | 기준 |
| --- | --- | --- |
| 기능 구현 완성도 | 30 | 선택한 개선안이 실제로 동작하는가 |
| Before/After 실측 비교 | 10 (보너스) | 같은 입력으로 개선 전/후를 돌려 수치(지연시간, 비용, 검색 정확도, retry 횟수 등)로 차이를 제시했는가 |
| 기술 요소 반영 | 30 | Multi-Agent, MCP, RAG, 의존성 주입, LangSmith, 모듈화, 단위 테스트 등이 충분히 고려됐는가 |
| 한계·트레이드오프 설명 | 20 | 개선이 새로 만든 약점(예: 벡터 DB 도입 시 임베딩 비용·지연, 그래프 탐색 시 무한 루프 가능성)을 스스로 짚었는가 |
| 발표 PPT 작성 및 발표 | 20 | 문제 → 개선/추가 포인트 → Before/After 수치 → 한계 및 추가 개선 사항 순서 |
