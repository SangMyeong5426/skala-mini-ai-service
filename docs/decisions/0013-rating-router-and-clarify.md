# 0013: 등급 점검 라우팅과 되묻기 — 과제 1 의미 라우터를 다시 쓰고, 설명이 없으면 묻는다

- 상태: Accepted
- 날짜: 2026-10-20
- 계획 항목: [`01-plan.md`](../01-plan.md) 순번 5·6 · 과제 1 [0003](0003-semantic-router.md)·[0004](0004-target-resolver.md)

## 문제

LLM 단독(Before)에서 두 가지가 드러났다(2026-10-20 `before0`, 평가셋 기준).

- **분류(qwen3:0.6b)가 점검 요청을 전부 일반 대화로 보냈다** — 라우팅 30문항 중 15/30, 점검 요청 15개를 모두 chat 으로.
  회귀 쿼리 11턴도 전부 chat 으로 가서 점검 경로를 한 번도 타지 않았다.
- **설명이 없어도 등급을 찍는다** — 되묻기 평가셋 12문항 중 6/12(되물어야 할 6개를 모두 그냥 판정).

## 검토한 선택지

### 라우팅

- A. 분류 프롬프트를 고친다 — 0.6b 는 과제 1에서도 프롬프트만으로는 오분류를 못 줄였다(0003).
- **B. 과제 1 의미 라우터를 그대로 쓰고 예시 문장만 바꾼다** — `SemanticRouter`의 라벨(`incident`)을 인자(`work_label`)로 일반화.

### 되묻기

- C. 길이 규칙만 — 짧은 요청은 잡지만, 길어도 내용이 없는 질문("저희 회사 신작 PC 게임이 심의를 받으면…")을 못 잡는다.
- D. LLM 에게만 묻는다 — "등급 예상해 줘" 같은 질문에도 판정 LLM 호출(약 15초)이 든다.
- **E. 둘 다 — 싼 것부터.** 판정 전에 길이 규칙, 판정 후에 판정 LLM 의 `described`.

## 결정

**B와 E를 택한다.**

- 예시 문장 `data/ratings/router_examples.json`(chat 15 · review 15)은 평가셋과 겹치지 않게 따로 썼다.
- 판정 기준은 평가셋이 아니라 예시 문장으로 정했다(`tools/tune_embedding.py --domain rating`, `runs/tune-embedding-rating_*.json`).
  - 지시문 없이 leave-one-out 0.867, 붙이면 0.833 — 과제 1처럼 지시문 없이.
  - 과제 1의 규칙(틀린 예시의 |gap| 최댓값 + 0.005)은 margin 0.066을 주는데, 그러면 예시의 절반 가까이를 대체 LLM 에 넘긴다.
    그 LLM(0.6b)은 **예시 문장에서도 16/30**밖에 못 맞힌다. 그래서 "margin 위는 의미 판정 + 아래는 대체 LLM"의 예시 정답률이
    가장 높은 margin 을 골랐다 — **0.04**(결합 정답률 0.967). 대체 LLM 의 정답률도 평가셋이 아니라 예시 문장으로 쟀다.
- 되묻기 직후의 다음 턴은 라우터를 거치지 않고 점검으로 보낸다(`clarify-followup`). 보충 설명만 보면 일반 대화로 분류될 수 있고
  ("피는 안 나와요"), 보충 설명만으로 판정하면 첫 질문의 내용(장르·플랫폼)을 잃는다 — 이전 질문과 이어 붙여 판정한다.
- 길이 규칙의 기준은 띄어쓰기 뺀 15자다 — 요청 문구 한 문장("우리 게임 몇 세 등급 받을까요?", 13자)은 걸리고, 짧아도 내용이 있는
  설명("고양이가 상자에 숨어 생선을 모으는 퍼즐", 18자)은 지나간다. 평가셋으로 고르지 않았다.

## 한계와 트레이드오프

- 예시 문장 30개로 정한 기준이다. 예시와 결이 다른 질문(영어, 긴 기획서 붙여넣기)에서는 기준이 맞지 않을 수 있다.

  설명해 달라"고 안내한다.
- 되묻기 ②는 판정 LLM 호출이 끝난 뒤에 정해진다 — 내용 없는 긴 질문도 약 15초를 쓴 뒤 되묻는다.
