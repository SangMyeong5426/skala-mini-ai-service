# 0014: 상세 설명 평가셋 B — 위원회 결정서 사유에서 결론을 지워 입력으로

- 상태: Accepted
- 날짜: 2026-10-20
- 계획 항목: [`01-plan.md`](../01-plan.md) 측정 계획(평가셋 B)

## 문제

평가셋 A(실제 게임 40개)의 입력은 게임물관리위원회 API 의 한 문장 개요다(중앙값 43자). 등급을 가른 표현(선혈, 노출 수위 등)이
개요에 거의 없어 정확도 상한이 낮다. 실제 사용은 개발자가 자기 게임을 자세히 설명하는 모양이라, 상세 설명일 때의 성능을 따로 봐야 한다.

## 검토한 선택지

### A. 평가셋 A 의 문항을 상세하게 다시 쓴다

쓰는 사람이 정답 등급을 이미 안다. 정답에 맞는 내용을 지어 넣게 돼 답이 샌다. 결과를 본 뒤 평가셋을 고치지 않는다는 약속(0010)과도 어긋난다.

### B. 가상 게임을 상세하게 쓰고 사람이 정답을 매긴다

정답이 실제 결정이 아니다. 코드를 쓴 사람이 정답까지 매기면 같은 기준표로 문제와 답을 만드는 셈이다.

### C. 위원회 결정서의 등급분류 사유를 입력으로 쓴다

공공데이터포털 「게임물관리위원회_등급분류증명서 및 결정서 정보」(2026년 2분기, 167건, 공공누리 1유형)에는 위원회가 쓴 사유가 있다 —
"개요 ＊ 기준어 - 상세 서술 … 따라서 … ‘15세이용가’로 등급분류 결정함." 정답은 같은 등급분류번호의 API 결정 등급이다.

## 결정

**C를 택한다** (사용자와 합의, 2026-10-20).

- 결론("따라서 …" 또는 "게임산업진흥에 관한 법률 …"부터 끝까지)과 "＊ 기준어" 머리를 지우고 개요와 상세 서술만 남긴다.
  남은 입력에 등급 이름·"이용가"·"등급"·"제7조"가 없는지 생성 도구와 테스트가 확인한다.
- A 와 같은 규칙(사행성 게임물 제외 등)으로 거르고, 간소화 설문 결정(내용 서술 없음, 54건)은 뺀다. 남은 39건을 모두 쓴다.
- 이 게임들은 사례 DB 기간(2026-04~06)에 있다. 평가할 때 자기 자신과 같은 제목(띄어쓰기·대소문자 무시)의 사례는 검색에서 뺀다
  (`CaseRetriever.exclude`, `tools/eval_rating.py rateb`).
- 기준선도 함께 잰다(`rbase`) — LLM 없이 사례만으로(가장 가까운 1건, 5건 다수결), 늘 최빈 등급.

## 한계와 트레이드오프

- **심의자의 말투다.** 서술에 "사실적으로 묘사", "경미하게", "제한적인 선정적 신체노출" 같은 기준표에 가까운 낱말이 남는다.
  개발자가 쓰는 설명보다 쉬울 수 있다 — B의 정확도는 상세 설명일 때의 상한에 가깝게 읽어야 한다.
- **등급이 고르지 않다**(전체 3 · 12세 7 · 15세 10 · 청소년이용불가 19). 늘 청소년이용불가라고 답해도 19/39(49%)다. 그래서 기준선과 함께만 읽는다.
- 같은 게임의 다른 판(제목이 조금 다른 리마스터·확장팩)은 제외 규칙에 걸리지 않아 검색될 수 있다.
- 사례 DB 기간 안의 게임이라 통계 Tool 의 집계에는 자기 자신이 1건 들어 있다(보고서에만 쓰고 판정에는 쓰지 않는다).
- 39건으로는 작은 차이를 가리지 못한다.
