# 0017: 사례 DB 쏠림 바로잡기 — 개요 없는 간소화 등급분류 결정도 넣는다

- 상태: Accepted
- 날짜: 2026-10-20
- 계획 항목: [`01-plan.md`](../01-plan.md) 순번 1·3 · [0010](0010-rating-data-and-evalsets.md) 수정 · [0016](0016-combine-cases-and-criteria.md) 다시 고르기

## 문제

결합 규칙 R1(사례 등급을 하한으로, 0016)을 넣자 회귀 쿼리에서 평범한 게임 6개 중 4개가 청소년이용불가로 올라갔다 — 귀여운 고양이 블록 퍼즐,
피가 나오지 않는 좀비 게임 등. 가장 가까운 사례가 성인 게임이었다. 사례 DB 의 모바일 사례 223건 중 청소년이용불가가 181건(77%)이었다.

처음에는 이 쏠림을 "모바일 오픈마켓 게임은 자체등급분류사업자가 매기고 위원회에는 청소년이용불가만 온다"로 짐작했다(0010). 원자료를 다시 보니
**주된 원인은 사례 DB 를 만든 필터**였다.

## 원인

| 사례 기간 모바일 결정 (연령 등급, 사행성 장르 제외) | 전체 | 개요 있음(필터 통과) | 개요 없음 — 번호 SC- |
| --- | ---: | ---: | ---: |
| 전체이용가 | 293 | 34 | 259 |
| 12세이용가 | 43 | 10 | 33 |
| 15세이용가 | 24 | 8 | 16 |
| 청소년이용불가 | 188 | 181 | 7 |

- 사례 DB 를 "개요가 있는 결정만"으로 만들었다(판단할 글이 없다는 이유).
- 개요가 없는 결정의 대부분은 **간소화 등급분류**다 — 게임산업법 제21조의10(등급분류 절차의 간소화)은 위원회가 온라인 시스템으로 등급을 매길 수 있게 하되
  **청소년이용불가와 게임제공업소용 게임물은 제외**한다(수집한 조문 `law/articles.json`). 이 결정은 번호가 `SC-`로 시작하고 게임 개요를 남기지 않는다.
- 그래서 "개요 있음" 필터가 낮은 등급의 모바일 게임을 체계적으로 지우고 청소년이용불가만 남겼다. 위원회의 실제 모바일 결정은 전체이용가가 53%다.
- PC·비디오 게임은 전체·12·15세를 게임콘텐츠등급분류위원회(번호 GC-)가 개요와 함께 기록해 쏠림이 작았다.
- 자체등급분류(오픈마켓)로 매겨지는 게임은 이 API 에 아예 없다 — 이 몫의 쏠림은 남아 있고 이번에 고치지 못했다.

## 검토한 선택지

### A. 모바일에서는 사례 등급을 쓰지 않는다

증상만 막는다. PC·비디오 게임에도 같은 필터가 걸려 있었고, 통계 Tool 의 분포도 그대로 틀린다.

### B. 사례 등급에 플랫폼별 보정치를 곱한다

보정치를 무엇으로 정할지가 또 문제가 된다.

### C. 개요가 없는 결정도 사례 DB 에 넣는다

실제 결정 분포를 되살린다. 개요가 없는 사례는 제목·장르·플랫폼으로만 검색된다 — 내용 근거로는 쓰이지 않고(내용정보도 대개 비어 있다), 등급 분포로만 작용한다.

## 결정

**C를 택한다.** `agent/rating/data.py`를 `usable_case`(사례 DB — 개요 불필요)와 `usable`(평가 입력 — 개요 필요)로 나눴다.

- 사례 DB 1,396 → **1,751건**. 모바일 사례의 청소년이용불가 비율 77% → **35%**. 통계 Tool 의 "퍼즐 · 모바일"은 38건 중 청불 28건 → 133건 중 전체이용가 99건.
- 평가셋 A·B·개발용은 입력에 글이 있어야 해서 그대로다(같은 문항). 다만 사례 DB 가 바뀌어 검색 결과가 달라지므로, 결합 규칙은 같은 후보·같은 기준으로
  개발용 문항에서 **다시 고른다**(0016).
- 과대평가를 따로 보려고 평범한 게임 10개(`rating_benign.json`)를 더했다 — R1 의 과대평가를 본 뒤에 쓴 점검 문항이다.

## 한계와 트레이드오프

- 평가셋 A·B 를 두 번째로 본다(R1 확인 뒤 데이터 수정). 같은 평가셋을 여러 번 보면 수치가 낙관적이 된다 — 규칙 선택은 여전히 개발용 문항으로만 한다.
- 개요 없는 사례는 제목만으로 비슷함을 잰다. 제목이 내용을 말해 주지 않으면(예: "행성게임") 검색이 장르·플랫폼 분포에 기댄다.
  평가셋 A 에서 실제로 3문항이 이 때문에 틀렸다(「미드나잇드림」·「마이드림키친」·「Short RPG」가 가장 가까운 사례로 뽑힘). 하한에는 개요 있는 사례만 쓰는 안은 followups.
- 자체등급분류(오픈마켓)로 매겨진 게임은 여전히 없다. 위원회 데이터 밖의 쏠림은 측정하지 못했다.
- 처음 0010에서 쏠림의 원인을 확인 없이 짐작해 적었다. 원자료로 확인하기 전까지는 원인을 단정하지 않았어야 했다.
