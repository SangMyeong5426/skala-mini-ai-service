# 0008: 답변 작성·검수 판정을 작은 모델로 바꾸는 시도 — 기각

- 상태: **Rejected** — 시험했고, 미리 정한 기준을 넘지 못해 채택하지 않았다
- 날짜: 2026-10-20
- 관련: [0002](0002-ollama-think-control.md)(thinking 제어), [0005](0005-grounded-validator.md)(검수)

## 문제

항목 1~5 적용 후 장애 질문 1건은 13~20초다(반복 3회 중앙값,
[`02-measurement.md`](../task1/02-measurement.md#발표용-수치--base--final2-반복-3회-중앙값-2026-10-20)). 그 대부분이 qwen3:8b
두 번 — 답변 작성 약 10초, 검수 판정 약 3.5초 — 이다. 남은 성능 개선의 가장 큰 지렛대는 모델 크기다.

## 시험한 것과 채택 기준

기준은 측정 전에 정했다. 하나라도 못 지키면 버린다.

| 시험 | 바꾼 것 | 채택 기준 |
| --- | --- | --- |
| A | 작성·판정 모두 qwen3.5:2b (로컬에 있던 2.3B 모델) | 판정 기준 + 작성 기준 |
| A′ | 작성만 qwen3.5:2b, 판정은 qwen3:8b | 작성 기준 |
| B | 판정만 qwen3:0.6b | 판정 기준 |

- **판정 기준**: judge 세트에서 오염 탐지 ≥ 6/7, 정상 오탐 0/5 (지금 8b 수준)
- **작성 기준**: judge 세트 정상 5건의 입력으로 쓴 초안이 모두 번호 형식·수치 대조·기준 판정(8b) 통과, 그리고
  **하지 않은 조치를 했다고 쓰지 않을 것** — 에이전트는 조회만 하고 조치는 하지 않으므로 "재시작했습니다" 같은
  완료형 주장은 보고서를 거짓으로 만든다.

도구: [`tools/try_models.py`](../../tools/try_models.py), 원자료: `runs/try-models_20261020-142735.json`.
모든 호출은 지금 운영 설정과 같은 `think=false`다.

## 결정

**세 시험 모두 기각하고 지금 구성(작성·판정 qwen3:8b)을 유지한다.**

- A·A′: 2b 작성은 40% 빠르지만 5건 중 3건이 하지 않은 조치를 완료했다고 쓴다. 장애 대응 보고서에서 "이미
  재시작했다"고 잘못 알리는 것은 늦는 것보다 위험하다.
- A·B: 작은 판정 모델은 오염을 놓치거나(2b), 모든 초안을 떨어뜨린다(0.6b). 0.6b를 쓰면 정상 답변도 재작성 3회를
  돌고 경고가 붙어 나가므로 오히려 느려진다.

## 한계와 트레이드오프 — 이 시험이 드러낸 것

- **지금 검수(8b 판정)도 거짓 완료 주장을 못 잡는다.** 2b의 초안 3건이 모두 기준 판정을 통과했다. 판정 기준이
  "질문과 관련 있는가 · 수치·상태·결론이 사실과 맞는가"뿐이라 "하지 않은 조치를 했다고 주장하는가"를 묻지 않는다.
  지금 작성 모델(8b)은 이런 문장을 쓰지 않았지만(0/5), 막는 장치는 없다 —
  [`followups.md`](../followups.md)에 판정 기준·평가 세트 보강을 남긴다.
- 성능 개선은 여기서 멈춘다. 장애 질문 1건 13~20초 가운데 약 13.5초가 8b 작성·판정이고, 이를 줄이는 다른 길
  (더 빠른 기기, 품질이 검증된 작은 모델)은 이 과제 범위 밖이다.
- 표본이 작다(작성 5건, 판정 12건). 2b에 thinking을 켜거나 프롬프트를 고치면 결과가 달라질 수 있지만, 시험하지 않았다.
