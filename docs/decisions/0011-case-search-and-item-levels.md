# 0011: 유사 사례 검색 + 항목별 단계 판정 — 등급은 코드가 최댓값으로 계산하고, 근거 없는 항목은 지운다

- 상태: Accepted
- 날짜: 2026-10-20
- 계획 항목: [`01-plan.md`](../01-plan.md) 순번 2·3 · 설계 [`03-design.md`](../03-design.md)

## 문제

LLM 단독(Before)은 게임 설명만 보고 등급을 바로 답한다. 실제로 불러 보니 두 가지가 드러났다(2026-10-20, qwen3:8b).

- 근거를 확인할 수 없다. 평가셋 a32(실제 청소년이용불가·사행성)를 "전체이용가"라고 하면서 내용정보는 7개 항목을 전부 붙였다 —
  등급과 내용정보가 서로 맞지 않는다.
- 게임물관리위원회가 실제로 어떻게 결정했는지 모른다. 같은 시리즈·같은 소재의 과거 결정이 있어도 쓰지 않는다.

## 검토한 선택지

### A. 프롬프트에 기준표만 넣고 LLM 이 등급을 답한다

근거는 늘지만 등급과 항목이 어긋나는 문제는 그대로다.

### B. LLM 은 항목별 단계와 근거만 내고, 등급은 코드가 계산한다

사례집 요약표의 4단계 열이 곧 연령 등급이다(전체·12·15·청소년이용불가). 그래서 **등급 = 해당 항목 단계의 최댓값**으로 계산할 수 있다.
등급과 항목이 어긋날 수 없다.

### C. B + 유사 사례 검색 + 근거 검사

사례 DB(1,396건)의 개요를 임베딩해 두고(`qwen3-embedding:0.6b`) 게임 설명과 가까운 실제 결정 5건을 판정 프롬프트에 넣는다.
근거는 **설명 속 구절** 또는 **검색된 사례 중 그 항목이 붙은 사례**만 인정하고, 코드가 확인해 아니면 그 항목을 지운다.

## 결정

**C를 택한다.**

- `agent/rating/cases.py` — `CaseRetriever`. 사례 DB는 MCP Resource(`ratings://cases`)로 받고, 기동 때 한 번 임베딩한다(캐시 있음).
  검색 범위는 장르+플랫폼 → 플랫폼 → 전체 순으로만 넓어지고, 사례가 3건보다 적으면 `replan_check`가 범위를 넓혀 다시 조사한다
  (과제 1의 재조사 루프를 그대로 쓴다).
- 통계 Tool(`rating_stats`)은 보고서에만 쓰고 판정 프롬프트에는 넣지 않는다. 위원회 데이터는 모바일에서 청소년이용불가 쪽으로 쏠려 있어
  ([0010](0010-rating-data-and-evalsets.md)) 판정을 끌어올릴 수 있다.
- `agent/rating/assess.py` — LLM(qwen3:8b)이 낸 항목마다 근거를 검사한다. 설명 구절은 띄어쓰기·문장부호를 지운 뒤 그대로 있거나
  2글자 조각의 80% 이상이 설명에 있으면 인정한다. 한 글자 근거는 인정하지 않는다. 사례 근거는 검색된 사례이고 그 사례에 같은 항목이
  붙어 있을 때만 인정한다.
- 등급이 가장 높은 항목 하나로 정해지므로, 한 항목의 과대평가가 곧 전체 과대평가다. 근거 없는 항목을 지우는 것이 이 위험을 줄인다.
  같은 이유로 항목을 나눠 따로 심사하는 구조는 쓰지 않았다([0009](0009-rating-domain.md)).

## Before/After

[`02-measurement.md`](../02-measurement.md) — 같은 커밋에서 스위치만 바꿔 쟀다.

| 평가셋 | LLM 단독 | 에이전트 | 기준표만(사례 검색 끔) | 사례 1건 기준선 |
| --- | ---: | ---: | ---: | ---: |
| A 한 문장 개요 (40) | 14 | 18 | 8 | **23** |

## 한계와 트레이드오프

- **"최댓값 = 등급"은 요약표를 그대로 읽은 규칙이다.** 실제 위원회는 주제·맥락까지 종합해 판단한다. 요약표가 주지 않는 판단은 이 규칙이 못 한다.
- **사례 근거는 "같은 항목이 붙었다"까지만 코드가 확인한다.** 그 사례가 정말 같은 성격의 게임인지는 LLM 판단이다. 비슷하지 않은 사례를
  근거로 단계를 올릴 수 있다.
- **같은 신청자의 비슷한 게임이 사례로 검색되면 답이 새는 것처럼 작동한다**(평가셋 A 40개 중 29개). 결과를 나눠 본다.
- 근거 검사가 엄격하면, LLM 이 구절을 바꿔 써서 맞는 판정도 지워질 수 있다(과소평가). 지운 항목은 판정 결과의 `dropped`에 남긴다.
- **두 부품이 서로 다른 입력에서 강하고, 지금 결합은 어느 쪽에서도 최선이 아니다.** 한 문장 개요에서는 사례 1건만 보는 기준선(23/40)이,
  상세 설명에서는 기준표만 쓴 판정(28/39)이 에이전트보다 높다. 사례를 "항목 근거"로만 쓰고 등급은 최댓값으로 정하니, 설명이 얇으면
  사례 등급을 살리지 못하고, 설명이 두꺼우면 사례가 등급을 끌어올린다(B 에서 4문항이 갈려 3문항이 나빠짐).
- 기동 비용: 사례 1,396건 임베딩. 캐시가 없을 때만 든다. 질문마다 임베딩 1회와 1,396건 코사인 계산(파이썬)이 더해진다.
- 판정 LLM 호출 1회(qwen3:8b, JSON 스키마)가 더해진다 — LLM 단독의 `rate_direct` 1회를 대신한다.
